# תוכנית אימונים ותזונה זוגית

אתר סטטי (HTML/CSS/JS רגיל, בלי build ובלי frameworks) שמתארח חינם ב-GitHub Pages:
**https://omer011210.github.io/eliram_fitness/**

## מה יש באתר
- **היום** – האתר נפתח על היום הנוכחי. אפשר לסמן כל תרגיל וכל ארוחה (הסימונים מתאפסים כל שבוע), ולרשום משקל וחזרות לכל תרגיל. הערך הקודם מוצג ליד השדה.
- **לוח אימונים שבועי** ו**תפריט זוגי** – עריכה ישירה, גרירה (עובדת גם במגע), העברה בין ימים, הסרה ושחזור.
- **פרופילים** – השמות (ברירת מחדל: אלירם ודוריאן) מחליפים את "עבורך / עבורה". המתג "הצג רק שלי" מסתיר את החלק של השני/ה.
- **Offline / PWA** – אחרי הביקור הראשון האתר עובד גם בלי קליטה, ואפשר להוסיף אותו למסך הבית.
- **סנכרון זוגי** (Firebase, לא חובה) ו**שתף קישור** (עובד תמיד, גם בלי Firebase).

## מבנה הקבצים
```
index.html              הדף
css/styles.css          עיצוב (כולל מצב כהה)
js/app.js               כל הלוגיקה
js/sync.js              סנכרון Firestore (נטען רק אם הוגדר Firebase)
js/firebase-config.js   ← כאן מדביקים את הגדרות Firebase
firestore.rules         כללי האבטחה להעתקה ל-Firebase
sw.js                   Service Worker (offline)
manifest.webmanifest, icons/, og.png, .nojekyll
```

## 1. הפעלת GitHub Pages
1. ב-GitHub: **Settings ← Pages**.
2. תחת **Build and deployment**: Source = **Deploy from a branch**, Branch = **main**, תיקייה = **/ (root)** ← **Save**.
3. אחרי דקה-שתיים האתר עולה בכתובת https://omer011210.github.io/eliram_fitness/

> **כשמעדכנים קבצים בעתיד:** צריך להעלות ב-1 את `VERSION` בראש `sw.js` (למשל `'v2'`), אחרת הטלפונים ימשיכו להציג את הגרסה השמורה. אחרי עדכון יופיע באתר "גרסה חדשה מוכנה ← רענון".

## 2. הקמת Firebase לסנכרון (חינם, תוכנית Spark)
הצעד הזה לא חובה. בלעדיו כל טלפון שומר את הנתונים של עצמו, ומעבירים ביניהם עם "שתף קישור".

1. נכנסים ל-https://console.firebase.google.com ← **Create a project**. שם לבחירתכם (למשל `eliram-fitness`). את Google Analytics אפשר לכבות. התוכנית נשארת **Spark (חינם)**, בלי כרטיס אשראי.
2. **הוספת אפליקציית Web:** במסך הפרויקט לוחצים על האייקון `</>` (Web) ← נותנים כינוי ← **Register app** (בלי Firebase Hosting). מופיע אובייקט `firebaseConfig`.
3. פותחים את `js/firebase-config.js` ומחליפים כל `PASTE_...` בערך המתאים מ-`firebaseConfig` (apiKey, authDomain, projectId, storageBucket, messagingSenderId, appId). הערכים האלה אינם סודיים, ומותר שיהיו בריפו ציבורי.
4. **התחברות אנונימית:** בתפריט **Build ← Authentication ← Get started ← Sign-in method ← Anonymous ← Enable ← Save**.
5. **דומיין מורשה:** באותו מסך: **Authentication ← Settings ← Authorized domains ← Add domain** ← `omer011210.github.io`.
6. **מסד נתונים:** **Build ← Firestore Database ← Create database** ← בוחרים מיקום (למשל `eur3 (europe-west)`) ← **Start in production mode**.
7. **כללי אבטחה:** ב-Firestore ← לשונית **Rules** ← מוחקים הכול, מדביקים את התוכן של `firestore.rules` מהריפו ← **Publish**.
   מה הכללים עושים:
   - גישה רק למסמך `pairs/<קוד-זוג>` ורק למשתמש מחובר (אנונימי).
   - הקוד חייב להיות בפורמט `XXXX-XXXX-XXXX-XXXX` (16 תווים אקראיים, כ-80 ביט). אי אפשר לנחש אותו.
   - אסור לרשום (`list`) את המסמכים, כך שבלי הקוד אי אפשר למצוא את הנתונים. גם מחיקה חסומה.
   - רק השדות של האתר מותרים, עם הגבלת גודל, וכל השאר במסד חסום.
8. עושים commit ל-`js/firebase-config.js`, מעלים ב-1 את `VERSION` ב-`sw.js`, ו-Pages יתעדכן תוך דקה.

**חיבור הטלפונים:** בטלפון אחד: ⚙ ← **צור קוד זוג חדש** ← **📨 שלח קישור הצטרפות** (לוואטסאפ). בטלפון השני פותחים את הקישור ← **הצטרפות**. מעכשיו כל סימון, משקל או עריכה מופיעים אצל שניהם תוך שניות. בלי קליטה הנתונים נשמרים במכשיר ונשלחים כשהחיבור חוזר. הנקודה על כפתור ⚙ מראה את מצב הסנכרון: ירוק = מסונכרן, כתום = שומר או מתחבר, אדום = שגיאה.
